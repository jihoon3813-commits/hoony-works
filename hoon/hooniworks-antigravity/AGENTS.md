# 후니웍스 개발 원칙

- README.md 및 docs/의 아키텍처·개발 명세·검수 기준을 읽는다.
- 서비스 이름은 후니웍스(HooniWorks). 120pie&coffee는 첫 번째 상품이다. 공통 화면을 특정 업종·상품의 문구나 이미지에 묶지 않는다.
- 공통 보라색 UI와 상품별 브랜드 표현을 구분하고 기존 작업 동선을 보존한다.
- workspaceId를 캠페인·자료·템플릿·결과물·생성 작업·계정 연결·게시 기록에 유지한다. 서버는 모든 요청에서 사용자 권한과 레코드의 workspaceId를 검사한다.
- 기본 designMode는 creative. reference와 template도 지원한다. creative/reference를 템플릿 ID 필수 흐름으로 바꾸지 않는다.
- 현재 구성 예시를 실제 콘셉트 생성으로 표시하지 않는다. 외부 API 응답과 결과물 저장을 확인한 작업만 완료 처리한다.
- 실제 제품·서비스 사진, 로고, 참고 이미지, 생성 배경과 텍스트 레이어를 구분한다. 원본을 덮어쓰지 않는다.
- 가격·효과·수익·실적·매장 수·후기·상품 조건은 승인된 근거만 사용한다. 서로 다른 상품의 사실을 혼합하지 않는다.
- API 키·OAuth 토큰은 서버에서만 관리한다. 브라우저 공개 환경변수, 로그, ZIP에 넣지 않는다.
- URL 등록과 OAuth 인증, 게시 준비와 게시 완료, 장면표와 MP4를 구분한다.
- 실제 유료 생성·게시·고객 메시지는 구체적인 사용자 지시 범위를 지킨다. 테스트를 실제 발송으로 대체하지 않는다.
- 부분 수정은 해당 콘텐츠 버전의 승인 상태를 무효화한다. 중복 생성·과금·게시를 막고 타임아웃은 공급자 상태를 먼저 확인한다.
- 브라우저 데이터 가져오기는 사용자가 실행하고 성공 건수·실패 목록을 확인할 수 있어야 한다. 이전 성공 전에 기존 데이터를 삭제하지 않는다.
- 상태 구조 변경 후 `npm run check`, `npm test`와 관련 화면 검증을 수행한다. 명칭·문서만 변경할 때 불필요한 테스트를 추가하지 않는다.
- 완료 보고에는 실제 작동 기능과 미연결 기능, 실행 방법과 검증 결과를 구분한다.
