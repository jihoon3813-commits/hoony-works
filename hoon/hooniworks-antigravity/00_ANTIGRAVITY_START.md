# 안티그래비티 첫 작업 지시

아래 내용을 프로젝트를 연 안티그래비티 대화창에 전달하세요.

---

이 폴더의 **후니웍스(HooniWorks)**를 여러 상품의 마케팅 콘텐츠를 제작하는 프로그램으로 발전시켜 줘. 120pie 전용 프로그램이 아니다. 120pie&coffee는 첫 상품이고, 이후 식품·생활상품·케어·멤버십·서비스 등 상품을 계속 추가할 것이다.

먼저 README.md, AGENTS.md, docs/ARCHITECTURE_AND_MIGRATION.md, docs/DEVELOPMENT_SPEC.md, docs/ACCEPTANCE_CHECKLIST.md와 현재 소스를 읽고, npm start로 실행한 뒤 npm run check와 npm test를 수행해. docs/VALIDATION.md는 전달 시점 검증 기록이며 개발 이후 재검증을 대신하지 않는다.

현재는 정적 HTML/CSS/JavaScript로 만든 작동형 시안이다. 이미 있는 기능을 다시 만들거나 이름만 120에서 바꾸는 단계로 돌아가지 마. 후니웍스 보라색 공통 화면, 전체 대시보드, 상품 목록과 추가·전환, 상품별 작업실, 브랜드·채널 설정, 자료실·캠페인·템플릿·게시 준비 흐름을 유지해. 120pie의 상품 이미지와 캠페인은 해당 상품 안에만 남겨.

가장 중요한 원칙은 다음과 같다.

1. **상품별 데이터와 계정 분리.** 모든 캠페인·자료·콘텐츠·생성 작업·채널 연결·게시 기록에 workspaceId를 연결하고 서버에서 접근 권한을 검사한다. 브라우저의 현재 선택값만 믿고 다른 상품의 자료를 읽거나 게시하지 않는다.
2. **디자인을 템플릿에 제한하지 않기.** 현재 designMode 값은 creative / reference / template이다. 새 캠페인 기본값 creative를 유지한다. 새 콘셉트는 구도·타이포·사진 배치·메시지 구조가 다른 3안을 실제 기획하고 사용자가 선택하게 한다. 색상만 다른 3안은 안 된다. creative/reference에서 저장 템플릿 ID는 필수값이 아니다.
3. **상품 원본 보존.** 실제 제품·서비스 사진과 로고는 원본을 유지한다. 참고 이미지는 분위기·색감·구도 자료로 구분한다. 생성 배경, 편집 가능한 한글 문구, 제품 사진과 로고를 레이어로 분리한다. 생성 연출로 상품을 바꾸는 작업은 별도 선택으로 다룬다.
4. **실제 완료 상태만 표시.** 지금 구현된 것은 디자인 방식 선택·브리프 저장·편집 미리보기다. API가 호출되지 않은 화면을 새 디자인 생성 완료로 표시하지 않는다. 장면표는 MP4가 아니고, 채널 주소 등록은 OAuth 인증이 아니며, 게시 준비 저장은 실제 게시가 아니다.
5. **공급자 교체 가능.** 기획·카피·이미지는 OpenAI, 영상은 Google을 기본 후보로 검토하되 작업별 어댑터로 분리한다. 실제 모델명·SDK·가격·규격은 연결 시점 공식 문서로 확인한다. 현재 문서의 방향을 지원 기능 보장으로 해석하지 않는다.

다음 순서로 작업해.

- 먼저 현재 코드 구조와 보존해야 할 동작을 요약하고 단계별 계획을 짧게 제시한다.
- 상품별 상태와 UI 렌더링을 모듈로 나누되 회귀 테스트를 유지한다. 스크립트 순서와 이전 데이터 호환성을 깨뜨리지 않는다.
- 로그인·워크스페이스 권한·DB·원본 저장·사용자 요청에 따른 브라우저 자료 가져오기를 구현한다.
- 모의 공급자를 명확히 표시한 콘셉트 3안 비교·선택 UI와 생성 작업 큐를 만든다.
- 실제 기획 → 이미지 생성·원본 합성 → 부분 수정·내보내기 순으로 연결한다.
- 장면별 영상 생성과 편집을 분리해 자막·음성·음악·로고를 합성한 MP4를 출력한다.
- 상품별 채널 인증·최종 게시 검토·결과 추적을 연결한다. 공식 게시 연동을 확인할 수 없는 채널은 자료 내보내기와 관리자 게시 방식을 유지한다.

API 키와 OAuth 토큰은 서버 비밀 저장소에서만 취급하고, 브라우저·소스·로그·ZIP에 노출하지 마. 키를 채팅에 입력하라고 요구하지 말고 필요한 시점에 안전한 서버 설정 경로를 마련해. 실제 유료 생성·SNS 게시·고객 메시지 발송은 사용자가 구체적으로 지시한 범위에서만 수행하고, 일반 개발 테스트에는 모의 공급자와 테스트 자료를 사용해.

현재 저장 데이터와 실제 고객 자료를 삭제하거나 덮어쓰는 방식으로 이전하지 마. 실패·중복·권한·예산·다른 상품 접근 테스트를 포함해. 매 단계 완료 후 변경한 파일, 작동 범위, 검증 결과와 아직 연결하지 않은 기능을 구분해 보고해. 첫 단계부터 구현을 시작해.
