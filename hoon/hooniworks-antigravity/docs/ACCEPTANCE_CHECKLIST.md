# 개발 인수 검수 기준

아래 미체크 항목은 다음 개발·운영 환경의 검수 과제이다. 전달본에서 수행한 검증은 VALIDATION.md에서 구분한다.

## 설치·회귀

- [ ] 압축 해제한 폴더에서 npm start로 후니웍스가 열린다.
- [ ] npm run check 및 npm test가 통과한다.
- [ ] 기존 120pie 캠페인·사진·계정 정보가 유지된다.
- [ ] 새 상품은 빈 캠페인·이미지·채널 설정으로 시작한다.
- [ ] 상품을 바꿔도 캠페인·사진·내 템플릿·계정·게시 기록이 섞이지 않는다.
- [ ] 현재 상품 초기화가 다른 상품이나 브랜드·채널 설정을 지우지 않는다.
- [ ] 실제 사용 브라우저에서 PNG/TXT/콘텐츠 ZIP을 다운로드하고 파일·본문·해상도를 확인한다.

## 서버 데이터·이전

- [ ] 모든 레코드·파일·작업은 workspaceId와 접근 권한을 검사한다.
- [ ] 다른 상품 ID를 대입한 API 요청·파일 요청이 거절된다.
- [ ] 브라우저 가져오기에서 원본 누락·중복·부분 실패를 표시하고 재시도 가능하다.
- [ ] 이전 성공 전 기존 데이터를 삭제하지 않는다.
- [ ] 여러 탭·기기·사용자의 동시 편집에 버전 충돌 정책이 있다.
- [ ] 생성 중 상품 전환·새로고침·탭 종료 후에도 원래 작업의 대상·결과가 보존된다.

## 다양한 디자인

- [ ] 기본 creative 모드는 템플릿 선택 없이 실제 기획을 시작한다.
- [ ] 3안은 구도·타이포·메시지 구조가 다르고 색상만 바꾼 복제본이 아니다.
- [ ] 한 콘셉트만 다시 기획·선택하고 채널별 결과물에 반영할 수 있다.
- [ ] 실제 사진·로고와 참고 이미지의 역할을 바꿔 사용하지 않는다.
- [ ] 제품 원본을 유지하며 배경·문구·사진 레이어를 별도로 수정할 수 있다.
- [ ] 좋은 결과물을 해당 상품의 템플릿으로 저장할 수 있다.
- [ ] 모의 결과와 실제 생성 결과가 구분된다.

## 생성·비용·보안

- [ ] 실제 API 응답과 저장된 결과 파일을 확인한 작업만 완료로 표시한다.
- [ ] 문구 수정에 이미지·영상 API를 불필요하게 다시 호출하지 않는다.
- [ ] 부분 실패 재시도와 타임아웃 복구가 중복 과금을 만들지 않는다.
- [ ] 동시 작업에서도 서버 예산 예약·한도가 적용된다.
- [ ] API 키·OAuth 토큰이 브라우저·로그·파일 묶음에 없다.
- [ ] 악성·과대 업로드 및 내부 주소로 향하는 참고 URL을 거절한다.

## 영상·게시

- [ ] 장면표가 실제 MP4와 명확히 구분된다.
- [ ] 장면·자막·음성·음악·로고가 의도한 순서와 길이로 합성된다.
- [ ] 자막 수정은 편집만 다시 실행하고 장면 생성을 반복하지 않는다.
- [ ] 게시 전 상품·채널·실제 계정·콘텐츠 버전·공개 설정을 확인한다.
- [ ] 인증·권한·미디어 미완료 상태에서는 게시할 수 없다.
- [ ] 게시 준비, 수동 URL 기록, API 게시 성공이 각각 구분된다.
- [ ] 게시 타임아웃 후 중복 실행 없이 공급자 결과부터 확인한다.
- [ ] 수정된 콘텐츠를 이전 승인으로 게시하지 않는다.
- [ ] 실제 고객 메시지 발송은 일반 게시와 구분하고 사용자 지시 범위를 따른다.

## 화면·출력

- [ ] PC 및 360/390/768px에서 가려진 버튼·가로 넘침이 없다.
- [ ] 키보드로 상품 전환·모달·입력·저장·취소가 가능하다.
- [ ] 긴 상품명·한글 줄바꿈이 화면·PNG·MP4에서 잘리지 않는다.
- [ ] API 모델명이나 개발용 안내 문구가 고객 대상 결과물에 들어가지 않는다.
